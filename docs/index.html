SUSFS как модуль ядра. Без пересборки.SUSFS as a kernel module. No rebuild.

Загрузите .ko на штатное GKI-ядро: файлы, маунты и прочие следы root пропадают из вида приложений. Выгрузили модуль, и всё как было. Load a .ko on a stock GKI kernel and root traces (files, mounts and more) disappear from apps' view. Unload the module and everything is back as it was.

Что умеетWhat it does

Те же возможности SUSFS, но в загружаемом модуле. Каждое правило включается отдельно.The SUSFS feature set, packaged as a loadable module. Every rule is switched on separately.

sus_path
Скрывает файлы и каталоги от приложений: stat, open, листинг каталога.Hides files and directories from apps: stat, open, directory listings.
sus_mount
Убирает ваши маунты из mountinfo для процессов без su; есть try_umount.Removes your mounts from mountinfo for non-su processes; try_umount included.
sus_kstat
Подменяет inode и время в stat(), statx() и maps.Spoofs inode and timestamps in stat(), statx() and maps.
sus_map
Прячет отображённый файл в maps, smaps, map_files и pagemap.Hides the mapped file in maps, smaps, map_files and pagemap.
open_redirect
Перенаправляет open() одного файла на другой.Redirects open() of one file to another.
uname / cmdline
Подменяет uname и cmdline / bootconfig.Spoofs uname and cmdline / bootconfig.
avc_spoof
Чистит следы KernelSU в аудит-логе SELinux (AVC).Hides KernelSU traces in the SELinux AVC audit log.
hide_modules
Убирает выбранные модули из /proc/modules, включая сам susfs.Drops chosen modules, susfs itself included, from /proc/modules.
priority filter2.4.0
Скрывает выбранные UID приложений от getpriority, setpriority, ioprio_get и ioprio_set для недоверенных процессов (uid ≥ 10000).Hides selected app UIDs from getpriority, setpriority, ioprio_get and ioprio_set for untrusted processes (uid ≥ 10000).
sus_path UID filter2.4.0
Команда SUSFS 2.4.0 для привязки правил sus_path к UID приложений.SUSFS 2.4.0 command that ties sus_path rules to app UIDs.

УстановкаInstall

Выберите способ. Для большинства устройств с KernelSU подходит ZIP-модуль.Pick a method. For most KernelSU devices the ZIP module is the way to go.

  1. Скачайте SusFS-LKM-by-uran-<версия>.zip из Releases.Download SusFS-LKM-by-uran-<version>.zip from Releases.
  2. Прошейте его в менеджере KernelSU и перезагрузитесь.Flash it in the KernelSU manager and reboot.

Модуль сам выбирает .ko по /proc/sys/kernel/osrelease и грузит его с expose_proc=1, поэтому появляются узлы /proc/susfs_*. Если SUSFS уже есть в системе, загрузка пропускается. В безопасном режиме модуль тоже ничего не грузит.The module picks the .ko from /proc/sys/kernel/osrelease and loads it with expose_proc=1, so the /proc/susfs_* nodes appear. If SUSFS is already present, loading is skipped. Safe mode skips it too.

Ранняя загрузка (post-fs-data.d) включена по умолчанию. Чтобы выключить, создайте файл и перезагрузитесь:Early loading (post-fs-data.d) is on by default. To turn it off, create this file and reboot:

touch /data/adb/modules/susfs_guard_lkm/no_early_load

Нужный KMI можно задать вручную: впишите его в файл kmi_override внутри модуля, например android14-6.1.To force a KMI, write it into the kmi_override file inside the module, for example android14-6.1.

Удаление: отключите или удалите модуль и перезагрузитесь, либо выгрузите на лету:Removal: disable or remove the module and reboot, or unload it live:

rmmod susfs_guard_lkm
  1. Скачайте SusFS-LKM-by-uran-<версия>-<kmi>.ko для вашего ядра.Download SusFS-LKM-by-uran-<version>-<kmi>.ko for your kernel.
  2. Загрузите файл в менеджере LKM (например, FinaSU).Load the file in your LKM manager (FinaSU, for example).
  3. В карточке модуля должно быть «SusFS LKM by uran», версия и автор uran.The module card should read “SusFS LKM by uran”, the version and author uran.

Версия у релиза вида v2.4.0-r1, у сборки из CI вида v2.4.0-r1-<хэш>.A release is versioned v2.4.0-r1, a CI build v2.4.0-r1-<hash>.

Подходит, если нет ни ZIP-модуля, ни менеджера. Положите .ko на устройство и загрузите от root.Use this when you have neither the ZIP module nor a manager. Put the .ko on the device and load it as root.

С KernelSU:With KernelSU:

ksud insmod /data/adb/loader/susfs_guard_lkm.ko

Без KernelSU, загрузчиком susfs_insmod (лежит в ZIP, в bin/):Without KernelSU, using the susfs_insmod loader (inside the ZIP, in bin/):

susfs_insmod /data/adb/loader/susfs_guard_lkm.ko expose_proc=1

Узлы /proc/proc nodes

Правила задаются записью в узлы. Они есть, если модуль загружен с expose_proc=1. Прочитать список правил можно через cat.Rules are set by writing to these nodes. They exist when the module is loaded with expose_proc=1. Read the current rules with cat.

УзелNodeНазначениеPurpose
/proc/susfs_pathПравила sus_path, cat показывает список.sus_path rules; cat shows the list.
/proc/susfs_kstatПодмена stat / statx / maps.stat / statx / maps spoofing.
/proc/susfs_mapСкрытие отображённых файлов по inode.Hides mapped files by inode.
/proc/susfs_hide_mountsКакие маунты считаются «вашими» и скрываются.Which mounts count as yours and get hidden.
/proc/susfs_hide_modulesСкрытие модулей ядра в /proc/modules.Hides kernel modules in /proc/modules.
/proc/susfs_open_redirectПеренаправление open().open() redirection.
/proc/susfs_opathСамопроверка покрытия open(O_PATH), только чтение.Self-check of open(O_PATH) coverage, read-only.
/proc/susfs_enable_logЛог модуля: 0 или 1.Module log switch: 0 or 1.
/proc/susfs_avc_spoofПодмена AVC-лога: 0 или 1.AVC log spoofing: 0 or 1.
/proc/susfs_priorityФильтр UID для getpriority / ioprio (2.4.0).UID filter for getpriority / ioprio (2.4.0).

Подробные команды каждого узла описаны в PROC_INTERFACES оригинального проекта. В этом форке часть узлов может отличаться.Per-node commands are documented in the original project's PROC_INTERFACES. Some nodes may differ in this fork.

FAQ

Нужно ли пересобирать ядро?Do I need to rebuild the kernel?

Нет. Это отдельный .ko, берите тот, что совпадает с KMI вашего устройства.No. It is a standalone .ko; take the one that matches your device's KMI.

Как понять, какой у меня KMI?How do I find my KMI?

Выполните cat /proc/sys/kernel/osrelease. Строка 6.6.30-android15-… означает android15-6.6. ZIP-модуль определяет KMI сам.Run cat /proc/sys/kernel/osrelease. A string like 6.6.30-android15-… means android15-6.6. The ZIP module detects it for you.

Работает без KernelSU?Does it work without KernelSU?

Да, через загрузчик susfs_insmod из ZIP. Нужен root, arm64 и подходящее GKI-ядро.Yes, with the susfs_insmod loader from the ZIP. You need root, arm64 and a matching GKI kernel.

После прошивки нет /proc/susfs_*/proc/susfs_* is missing after flashing

Проверьте, что модуль загрузился: lsmod | grep susfs, и посмотрите load.log в папке модуля. Узлы создаются только при expose_proc=1. Если в ядре уже есть SUSFS, модуль не грузится.Check that the module loaded: lsmod | grep susfs, and read load.log in the module folder. The nodes are created only with expose_proc=1. If the kernel already has SUSFS, the module does not load.

Трогает ли это раздел ядра?Does it touch the kernel partition?

Нет. Модуль работает только в памяти. Отключите его, перезагрузитесь, и система чистая.No. The module lives in memory only. Disable it, reboot, and the system is clean.
